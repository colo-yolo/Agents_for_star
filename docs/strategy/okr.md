# Phase 0 OKR

周期: 2026-06-07 到 2026-06-21

## Objective 1: 在两周内把智能 AI 硬件 OPC 从想法收敛为可验证的 MVP 方向

KR1: 明确 3 个候选使用场景, 每个场景包含目标用户、核心痛点、替代方案和放弃条件。

KR2: 完成 10 次目标用户访谈或等价的一手需求验证记录, 每次记录包含原话摘要、痛点强度、现有替代方案和购买意愿线索。

KR3: 从 3 个候选场景中选择 1 个 Phase 1 POC 主场景, 并写入决策记录。

KR4: 为未选择场景写出保留、推迟或放弃原因, 防止路线图失焦。

## Objective 2: 建立一人公司多角色 Agent 的最小可执行操作系统

KR1: 完成所有核心 Agent 的协议模板, 至少覆盖战略、产品、硬件、固件、AI、后端、控制台、QA、供应链、合规、安全、财务、市场、销售、客户成功和知识运营。

KR2: 建立任务路由规则, 任意新任务必须能指定一个主 Agent、一个审查 Agent 和一个审批条件。

KR3: 建立风险登记册, 至少覆盖产品、硬件、供应链、隐私、安全、合规、财务和执行过载风险。

KR4: 建立决策记录模板, 所有高影响选择必须写入 `docs/decisions/`。

## Objective 3: 为 Phase 1 POC 建立可执行技术和经营准备

KR1: 完成 PRD v1, 包含目标用户、问题、MVP 范围、非目标、验收标准和首轮试点条件。

KR2: 完成 BOM 初稿模板, 至少覆盖主控、音频、视觉、输出、连接、电源、外壳和测试工具。

KR3: 完成隐私影响分析和威胁模型初稿, 所有高风险数据流必须有人工审批或禁用策略。

KR4: 完成经营指标表, 每周可追踪现金、成本、样机、访谈、缺陷、线索和 Agent 自动化率。

## 评分规则

- 0.0 到 0.3: 未形成可执行证据。
- 0.4 到 0.6: 有产出但缺少用户、技术或风险验证。
- 0.7 到 0.9: 主要目标达成, 可进入 Phase 1。
- 1.0: 所有 KR 有证据并完成复盘。

## 审批门槛

进入 Phase 1 前, 创始人必须确认:

- 主场景足够窄, 可以在 4 到 6 周内做 POC。
- 关键隐私和安全风险没有阻塞项。
- BOM 和云端成本在个人预算可承受范围内。
- 不进入量产承诺、预售承诺或对外法律承诺。
