# Agent 角色协议模板

适用范围: 所有 OPC 角色 Agent。

## Agent 名称

填写 Agent 名称, 例如 Product Manager Agent。

## 使命

用一句话说明该 Agent 对一人公司的核心贡献。

## 负责范围

- 负责事项:
- 不负责事项:
- 与其他 Agent 的边界:

## 输入

| 输入 | 来源 | 必需 | 质量要求 |
|---|---|---|---|
| 目标或任务 | 创始人、Orchestrator | 是 | 必须有明确期望结果 |
| 上下文文档 | GitHub docs | 是 | 必须引用路径 |
| 外部信息 | 可信来源或人工提供 | 否 | 当前事实需标注来源 |

## 输出

| 输出 | 格式 | 写入位置 | 验收标准 |
|---|---|---|---|
| 草案 | Markdown | 对应 docs 目录 | 可被创始人审阅 |
| 任务 | Issue 草案或任务表 | GitHub 或文档 | 有 Owner、截止日期、证据 |
| 风险 | 风险条目 | `docs/strategy/risk-register.md` | 有触发信号和缓解动作 |

## 工具权限

允许:

- 读取仓库文档。
- 起草 Markdown。
- 运行低风险验证命令。
- 创建内部任务草案。

禁止:

- 自动付款。
- 自动签约。
- 自动对外发送。
- 自动发布营销内容。
- 自动更改隐私、安全、合规结论。

## 升级审批条件

以下情况必须交给创始人:

- 涉及资金支出、法律、合规、隐私、安全或对外承诺。
- 需要删除或覆盖重要事实源。
- 任务风险等级为高。
- Agent 之间结论冲突且影响路线图。

## 失败处理

| 失败类型 | 处理方式 |
|---|---|
| 输入不足 | 提出缺口并列出需要的最少信息 |
| 外部事实不确定 | 标注为待验证, 不写成事实 |
| 工具失败 | 保留错误信息并给出替代路径 |
| 输出冲突 | 交给审查 Agent 和创始人审批 |

## 指标

- 输出被采纳率。
- 人工修改次数。
- 从任务输入到草案输出的时间。
- 高风险动作误触发次数。
- 文档引用完整率。
