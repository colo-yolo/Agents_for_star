# 高级硬件工程实践蒸馏

## 目的

为 Hardware Architect Agent 提供 Principal/Staff 级硬件工程工作方法。本文从开源硬件、PCB 评审、bring-up、开放硬件文档和硬件 CI 思路中提炼可落地规则。本文不包含器件报价、认证费用、供应商承诺或法律结论。

## Principal 级能力模型

| 能力 | 低级表现 | 高级表现 |
|---|---|---|
| 需求拆解 | 直接列器件 | 先定义使用场景、环境、功耗、热、隐私、合规、成本和测试约束 |
| 系统架构 | 选开发板 | 明确传感器、主控、电源、无线、显示、外壳、热路径和调试接口的边界 |
| 设计评审 | 看能不能工作 | 按 DRC/ERC、接口保护、去耦、测试点、DFM、DFT、DFA、热和安全逐项门控 |
| 风险管理 | 风险写一句 | 用 FMEA 记录失效模式、影响、严重度、发生度、检出度、RPN 和缓解动作 |
| Bring-up | 直接上电跑固件 | 限流、分轨、分模块、先硬件后固件、每一步保留测量证据 |
| 供应链 | 找最便宜器件 | 管理生命周期、替代料、MOQ、交期、认证模块和采购审批 |
| 跨团队接口 | 口头说明 | 输出接口控制文档、测试点、日志字段和固件交接要求 |
| 量产意识 | Demo 成功即推进 | POC、EVT、DVT、PVT 分阶段门控, 不越级承诺 |

## 设计评审核心规则

1. 原理图必须有电源树、接口保护、调试口、版本号和关键网络命名。
2. 每个电源轨必须有电压、电流、上电顺序、测量点、保护和纹波假设。
3. 高速、无线、音频、摄像头和 USB-C 等接口必须记录布局和连接器约束。
4. 传感器涉及隐私时, 必须提供物理指示、关闭路径和数据处理边界。
5. PCB 进入打样前必须有 DRC/ERC、制造约束、装配约束、测试点和 silkscreen 标识。
6. BOM 进入采购前必须有替代料、生命周期、来源、风险和审批状态。
7. 开发板 Demo 不等同于自研 PCB 风险关闭。

## Bring-up 核心规则

1. 上电前先目检、短路检查、极性检查和连接器方向检查。
2. 首次上电使用限流电源, 从最低风险路径开始。
3. 每个电源轨单独记录空载电压、负载电压、电流、纹波和温升。
4. 固件运行前先确认时钟、复位、调试口、启动模式和关键电源良好。
5. 任何异常发热、过流、复位抖动或通信失败都必须停止扩展测试并记录隔离实验。
6. bring-up 记录必须能让另一个工程师复现。

## 开源硬件引用边界

- 只把开源项目作为工程实践和参考设计线索, 不直接复制商业设计。
- 必须检查许可证、归属、商用限制、版本、依赖和适用边界。
- 参考项目的成功不代表本项目的认证、可靠性、成本或供应链已经验证。

## 对本项目的直接建议

1. Phase 1 继续使用开发板和外设组合, 不急于自研 PCB。
2. 如果进入自研 PCB, 先新增 KiCad 项目结构、DRC/ERC 规则和制造输出门禁。
3. 麦克风、摄像头、无线、USB-C、电池、充电和外壳热路径必须进入高风险评审。
4. 每次硬件决策都写入 `docs/hardware/` 或 `docs/audit/`。
