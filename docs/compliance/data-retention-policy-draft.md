# 数据保留政策草案

状态: 产品设计初稿, 不是法律意见。正式政策发布前必须由创始人和合格专业人士审查。

## 目的

为 Phase 1 POC 和后续试点定义数据最小化、保留、删除和审批原则。本文只用于内部产品设计, 不作为客户可见隐私政策。

## 数据分类

| 数据类型 | 示例 | 默认保留建议 | 风险等级 |
|---|---|---|---|
| 系统审计日志 | Agent、工具、审批状态 | 保留到项目复盘完成后由创始人决定 | 中 |
| 设备模拟输入 | 模拟按钮、模拟传感器事件 | POC 期间保留 | 低 |
| 用户访谈摘要 | 痛点、场景、非敏感引用 | 保留到研究结论复盘完成 | 中 |
| 原始访谈录音或截图 | 录音、屏幕截图、聊天记录 | 默认不采集, 如需采集必须审批 | 高 |
| 客户联系方式 | 姓名、邮箱、公司 | 默认由创始人管理 | 高 |
| 支付和合同资料 | 付款、报价、合同、NDA | Agent 不保存 | 高 |
| 生产密钥或令牌 | API key、设备证书 | Agent 不保存 | 高 |

## 默认原则

1. 只采集完成主场景验证所需的最小数据。
2. 未经创始人批准, 不采集原始音视频、敏感业务材料或客户联系方式。
3. POC 文档中出现的用户信息优先脱敏。
4. 外部模型或外部工具不得接收未授权敏感数据。
5. 数据保留到期后的删除或归档动作必须记录。

## 删除和归档

| 触发条件 | 建议处理 |
|---|---|
| POC 结束 | Knowledge Ops Agent 输出保留清单, 创始人决定归档或删除 |
| 用户要求删除 | 暂停相关处理, 创始人确认身份和范围 |
| 发现误采集敏感信息 | 立即标记高风险, Security 和 Compliance 审查 |
| 项目方向改变 | 重新评估数据继续保留的必要性 |

## 创始人审批事项

- 采集、保存或外发任何个人敏感信息。
- 使用真实客户资料进行模型评估。
- 修改默认保留周期。
- 删除审计日志、访谈原始记录或客户资料。
- 发布客户可见隐私政策或数据处理说明。

## 待验证事项

- 目标市场和适用法域未采集。
- 真实试点客户数据字段未采集。
- 正式隐私政策和数据处理协议由创始人安排专业审查。
