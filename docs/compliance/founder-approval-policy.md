# 创始人审批政策

状态: 产品设计初稿, 不是法律意见或公司治理文件。

## 目的

定义 Agent 和 Orchestrator 在一人公司场景下必须升级给创始人的动作, 防止自动化系统越权执行高风险事项。

## 审批原则

1. Agent 可以分析、起草、检查和建议, 不能代替创始人承担不可外包责任。
2. 高风险动作默认阻断, 进入审批队列。
3. 审批必须有上下文、风险说明、替代方案和回滚方式。
4. 未记录审批的高风险动作视为未批准。

## 必须审批的动作

| 类型 | 示例 | 审批要求 |
|---|---|---|
| 付款 | 样品采购、订阅、云资源、广告 | 创始人明确批准金额和对象 |
| 签约 | 合同、NDA、试点协议、采购条款 | 创始人批准, 必要时专业审查 |
| 对外发送 | 客户邮件、报价、发布文案、媒体材料 | 创始人批准接收方和内容 |
| 隐私策略 | 数据采集、保留、删除、客户可见隐私说明 | 创始人和 Compliance 审查 |
| 安全例外 | 权限提升、跳过鉴权、使用生产密钥 | 创始人和 Security 审查 |
| 量产承诺 | 交付日期、认证、产能、保修 | 创始人批准, 依据待验证 |
| 客户承诺 | SLA、补偿、价格、功能承诺 | 创始人批准 |

## 审批包格式

| 字段 | 说明 |
|---|---|
| 事项 | 需要批准的具体动作 |
| Owner Agent | 发起 Agent |
| 风险等级 | 低、中、高 |
| 输入来源 | 关联文档路径或由创始人填写 |
| 建议动作 | 批准、拒绝、延期、补充信息 |
| 影响范围 | 产品、财务、安全、合规、客户 |
| 回滚方式 | 如果判断错误如何撤回 |
| 截止时间 | 由创始人填写 |

## 审批状态

- `draft`: Agent 起草中。
- `needs_review`: 需要审查 Agent 复核。
- `pending_founder_approval`: 等待创始人审批。
- `approved`: 已批准, 必须记录范围。
- `rejected`: 已拒绝, 不得执行。
- `needs_more_info`: 信息不足, 暂停。
- `expired`: 超过有效期, 需重新提交。

## 失败处理

| 情况 | 处理 |
|---|---|
| 审批状态缺失 | 默认按未批准处理 |
| 审批范围不清 | 默认只批准最小范围, 其余继续阻断 |
| Agent 误触发高风险工具 | 立即停止, 记录审计日志并通知创始人 |
| 审批后事实变化 | 回到 `needs_review` |

## 待验证事项

- 审批通知渠道由创始人填写。
- 审批记录最终存储位置待验证。
- 是否需要电子签名或外部审批系统待验证。
